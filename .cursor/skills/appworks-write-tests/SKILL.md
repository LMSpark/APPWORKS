# 写出真正能抓住问题的测试

测试的价值是抓住一个具体的错误。这里只管测试质量，不改变"要不要写测试"的决定。

## 前置门禁

**方案批准了才写测试。** 根 `AGENTS.md` 规定计划外新增测试策略属于超范围变更。先确认 `notes/plan-*` 的验证计划包含这批测试；没有就停下，回到阶段 4 修订方案，不要先写。

## 原则一：每个测试说明它抓什么错

写测试体之前先回答：**什么生产代码改动会让这个测试失败？那个改动是 bug 还是一个有意的决定？**

- 回答不出来：围绕可观察行为重新设计。
- 期望值**独立推导**：用字面量或手算夹具，不用被测代码或其辅助函数算出来。同一个 builder 同时算两边是恒真的镜像断言。
- 不写"变更探测器"：只有有意修改才会失败的断言（常量取值、固定文案、私有结构）会在重构时误报、在 bug 时沉默。测依赖这个决定的行为，如"失败调用重试 5 次，第 6 次不发生"，而不是 `expect(MAX_RETRIES).toBe(5)`。
- 测**本仓代码的契约**（你注册的路由、你发出的查询、你产出的载荷），不测上游框架的文档行为。

## 原则二：测真实的东西

- **不对 mock 本身断言。** 断言真实组件的行为；如果断言的是 mock，要么去掉 mock，要么删掉这条断言。
- mock 在正确的层级：先弄清被替换方法的所有副作用，只替换慢或外部的那一层，测试依赖的副作用保持真实。
- mock 数据还原完整真实结构，不要只填测试读到的字段。
- mock 设置比测试逻辑还长，或总漏方法：改成用真实组件的集成测试。
- **生产类只放生产方法。** 只有测试会调用的清理方法放进测试工具，不要加到生产类上。

## 流程

1. 先确认方案范围内要测的行为。
2. 方案要求"先写失败测试"，或在修 bug 时：先写**复现问题**的测试，运行并确认它**因为预期原因而失败**（不是拼写错误、导入错误）。
3. 写最小实现使其通过，再运行确认通过且其他测试不受影响，输出无错误和警告。
4. 收尾做**变异检查**：设想改错一个常量/参数、走错分支、漏掉状态变更或副作用、返回空值或默认值、漏掉对空/零/未授权/格式错误输入的校验。每种现实的变异至少有一个测试会失败；没有就是行为无保护，或测试是同义反复。
5. 用 `appworks-verify-before-claim` 的标准报告结果。

## 本仓约束

- 测试同样受根 `AGENTS.md` 硬门禁约束：单目录源文件不超过 10 个（超过按被测模块拆子目录）；不用非 `as const` 的类型断言；不新增无消费者的导出。
- 运行单个测试：`pnpm exec vitest run <路径>`；单包：`pnpm --filter @spark-appworks/<pkg> run test:run`。命令与顺序见 `knowledge/testing.md`。
- 改过模型 class 的字段或 JSDoc 后，相关测试依赖生成物：先 `pnpm run generate:class-model-surface`。
- 不为覆盖率写测试：琐碎代码和给人看的文档不需要测试；只写行为需要的，别多写。

## 警告信号

- 测试里预置的对象和断言的对象是同一个，结果必然相等；
- 只可能因为崩溃或选择器缺失而失败；
- 每次有意修改都会失败，但从不因意外破坏而失败；
- 期望值藏在循环、builder 或辅助函数后面；
- 测试在读源码文本或断言"某个符号已被删除"；
- 断言的是 `*-mock` 标识，去掉 mock 断言就失败；
- 某个方法只被测试文件调用；
- mock "只是为了保险"。
