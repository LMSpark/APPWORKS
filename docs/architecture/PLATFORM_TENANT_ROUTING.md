# 平台、企业、项目蓝图与运行路由

AppWorks 以 lowcode 会话中的企业和应用身份建立运行作用域。项目蓝图表达完整项目策划；运行导航只是蓝图经过运行候选筛选和后端授权后的输出。

## 层级

```text
平台
  -> 企业 enterprise
      -> 应用 project
          -> 项目蓝图 ProjectBlueprint
              -> 模块 / 需求 / 原型 / 数据空间 / 页面 / 子页面 / 报表 / 流程 / 动作
```

- 企业身份来自 lowcode 登录会话。
- 应用身份来自 lowcode 应用目录和当前会话。
- 蓝图平铺记录来自平台数据库；前端只投影树，不创建第二套身份。
- 运行菜单由 `RuntimeNavigation` / `RuntimeNavigationItem` 表达，不等于完整项目蓝图。

## 蓝图与运行导航

```text
完整项目蓝图
  -> 可成为运行入口的候选节点
  -> 与后端授权集合相交
  -> RuntimeNavigation
  -> DynamicRouter
  -> Vue 页面或配置页面运行时
```

需求、原型、数据空间等隐藏节点必须保留在蓝图中，即使它们不进入运行菜单。外链、动作或模块节点也不能机械创建页面数据空间。

## 页面与数据空间

- `conid` 是历史场景 ID/FormKey；Vue 路径只负责组件寻址。
- 页面只能消费数据空间，不能直接把物理表名当作前端模型。
- 数据空间承载前端模型引用的数据资源、字段和关系。
- 页面运行闭包还需要导航 FormKey、输入、依赖以及后端权限结果。

## 前端作用域

URL 形式：

```text
/t/{enterpriseShortName}/{projectId}/{pagePath}
```

`src/services/tenant-scope.ts` 只负责解析和构造作用域路径。真实企业和应用必须与 lowcode 会话对账；浏览器不得从 cookie、任意 query 或本地默认值发明平台身份。

## 项目切换

```text
选择应用
  -> lowcode 激活应用上下文
  -> 读取完整项目蓝图
  -> 读取授权运行导航
  -> 注册动态路由
  -> 页面按 FormKey 与数据空间运行
```

## 关键约束

1. AppWorks 不拥有服务端，不保存平台数据库副本。
2. 项目蓝图不是菜单；运行菜单只是其授权输出之一。
3. 蓝图、物理数据资源、数据空间、前端模型和页面运行闭包身份必须分开。
4. 前端只按后端最终权限结果渲染，不按角色名或页面本地规则推导授权。
5. mutation 缺少治理能力时必须 fail-closed。
