## 当前决策与边界

- 新 APP 在 `D:/SPARK_AppWorks` 建设，使用独立资源；不绑定旧投标应用资源连接。此项是契约映射形成后的用户确认。
- 源码实现、冷回读、正式服务缺口和验收状态不在本 README 重复累计，统一由唯一台账记录。
- 用户要求避免与已有投标应用重名；已核正式目录中的旧应用“领码智能投标 / SMART_BID_DEMO”，并将本次新应用及根蓝图显示名改为“领码投标全生命周期平台”。保留本次应用ID和技术名称spark-bid，不另建应用，旧应用未改动。
- 不迁入旧应用实现、模型密钥、测试过程文件或历史构建产物。
- 正式方案中的原项目绝对路径是历史实现位置和复用线索，不能视为 AppWorks 运行绑定，也不能据此证明能力已经交付。后续实现以本仓正式合同及现场证据核对。
- 四份正式方案来源于原项目 `apps/smart-bid-demo/docs`；[业务规格入口](authoring-submission-specification.md) 及其 `contracts/` 分册只做文档结构整理，不通过改文档替代源码或服务验收。
- 平台实施与未决事项仍沿本仓[唯一台账](../../notes/data-space-retirement-ledger.md)，不另建平台迁移总计划。
