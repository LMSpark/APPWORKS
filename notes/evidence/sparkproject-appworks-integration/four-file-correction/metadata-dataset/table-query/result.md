## 闭环与责任

原生DataTable.api.list确定列表端点，crudConfig.timeout确定单次请求超时。此前正式查询固定GetData，忽略表级超时，ScenarioViewConfig还会拒绝list。本轮让同一配置经过文件保存、新ProjectWorkspace重开、正式Assembler装配、原DataView查询owner、每页HTTP请求及原查询签名保存，保持SPARK模型身份、封包、权限与回执消费。

将原DataSpaceSaveConfig迁为内部DataSpaceRequestConfig，查询与提交复用端点/策略校验；没有新增公共包出口，也没有另建权限或保存通道。为保存兼容保留既有SPARK_SAVE_CONFIG诊断码。该类迁移使生成消费清单的引用位置变化，按原生成器刷新；端点587项、消费者153项数量保持。

查询配置在等待同模型保存之前捕获，多页请求都使用该值。配置的URL、规范化请求头、参数和timeout参与在途去重键；等价配置共享请求，各自DataView仍持有独立运行行，不同配置不串结果。清除文件配置后重开恢复默认路由及默认超时行为。配置不能覆盖运行身份头，也不携带查询结果权限。
