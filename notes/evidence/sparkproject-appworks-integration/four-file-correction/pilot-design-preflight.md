### 对“需要设计 CRUD facade”的修正：先复用已有 DataView owner

- 四个 8D 设计 DataView 是正式的 query/save owner，不应因 `DataSpaceDesignApi.prepareMutation()` 只负责 prepare，就推论必须新增另一层 CRUD facade。具体表/视图绑定为 `config/pages/data-platform/data-space-design/pagedata.json` L2–80；当前设计脚本已 resolve 它们并用正式过滤字段读取（`config/pages/data-platform/data-space-design/script.js` L306–380），因此运行时有 DataView 所需的 query context、scenario/model identity 和字段权限快照。
- 可直接依序用的公共方法合同：`DataView.addRow()`（`packages/spark-data/src/data-view.ts` L1760–1777，查询视图先由 query executor `prepareNewRow`，然后进入本地待提交）；`editRowById()`（L1807–1824，捕获旧行、更新并跟踪 dirty）；`removeRow()`（L1785–1797，捕获删除行并跟踪 pending-delete）；`saveChanges()`（L1856–1865，将 query-backed view 转至 `saveQueryViews`）；`DataSet.saveChanges({views:[...]})` 能选择批次中的 view/row，并复用上述 owner。`DataView.saveQueryViews()`（L1867–1912）限定同一 executor、同一 scenario、每个 model identity 唯一，并校验每模型回执及 query context 未变化后才接纳结果。query-backed 视图不会因默认 `commitMode='immediate'` 走裸 CrudApi：`shouldDirectCommitCrud()` L702–712 在 `#queryExecutor` 存在时固定返回 false。
- 已验证的目录 add/edit 链是可复用范例，而非新增 API：`config/pages/data-platform/data-space-catalog/script.js` L301–325 对 `addActionState`、新增行、未知回执和 refresh 有序处理；L351–429 按字段 write/read 权限构造 patch，调用 `editRowById` → `DataSet.saveChanges` → refresh 并独立报告刷新失败。对应现有测试 `tests/runtime/page/catalog/data-space-four-file.test.ts` L1382–1394 验新增回执/正式 rowid，L1689–1708 验仅提交可编辑字段；故设计 CRUD 优先改为用 8D 四个 view 的同类链，写后 refresh/readback 验明正式行。当前设计四 view 的页面脚本本身仍只读，设计操作接线和权限配置还未在线验收；不要把目录测试替代设计场景验收。

## 非 DataView 草稿的 PageRuntime 生命周期闭环（本次只读核实）

- **正式 owner 现状**：`packages/spark-project-model/src/page/runtime-page.ts` L11–18 的 `PageRuntimeOptions` 只有工具、场景及装载回调；L54 当前 `isDirty` 只遍历本实例 DataSet 下 DataView 的 `dirtyTracking` 和 `editingRows`；L74–81 的 load 将每个独立 DataSet 收到本实例，L103–106 的 dispose 无条件销毁并清空这些 DataSet。没有非 DataView 草稿容器，也没有 dispose 前的 dirty 检查。此前报告提出“PageRuntime 汇总图 dirty”的方向仍成立，但不能以组件局部 boolean 或卸载时解绑的临时 contributor 代替 runtime 生命周期状态。
- **managed route 的缓存与保护实际配合**：`src/App.vue` L96–98 对 managed page view 使用 `<KeepAlive :include="runtimeNames">`，runtimeName 来自每个 pool entry 的 view（`packages/spark-app/src/navigation/useTabPages.ts` L42–73）。multi-tab 切到其它 route 时，原 tab 仍在列表、view name 仍在 include，renderer 被 KeepAlive 缓存，PageRuntime 留在 `PageRuntimePool`；只是视图暂时 deactivated，尚未关闭。标签关闭/关闭其它/关闭全部先 `assertClean`，活动标签先等待导航成功，再 `release`/`closePageRuntime`（`useTabPages.ts` L78–92、L138–154）；`setMode('single')` 和 single-mode 路由 `beforeEach` 也先检查 dirty 再释放（L102–108、L121–164）。`closePageRuntime` 自己再次检查 runtime.isDirty 后才 dispose 并从 pool 删除（`packages/spark-app/src/router/page-runtime-pool.ts` L145–152）。因此真实单/多标签正常路径会通过 PageRuntime dirty owner 阻止草稿关闭；多标签切换不销毁当前未激活页。
- **刷新/应用切换调用链**：刷新按钮在 `src/App.vue` L244–252 调活动 managed wrapper 暴露的 `reload`；pool wrapper L117–127 检查 `runtime.isDirty`、刷新 route、调用 `runtime.reload()` 后再调 renderer reload，`PageRuntime.reload()` L47–52 另做 dirty 检查。应用切换有两条正式入口：导航守卫在应用归属将变化时先 `dynamic.assertPageRuntimesClean()`，激活成功后 reset system pages、调用 `disposePageRuntimes()` 再刷新路由（`src/services/project/navigation/project-navigation-guard.ts` L59–75）；App 项目切换服务同样先 assert，完成应用选择后再 dispose（`src/App.vue` L382–401）。`disposePageRuntimes()` 自己再次 assert 再逐个 dispose 并清空 pool（`page-runtime-pool.ts` L154–164）。图/JSON 草稿一旦纳入同一个 runtime dirty owner，这些既有关闭、刷新、应用切换门禁可复用，无需在脚本里直调底层 save。

## PageRuntime 生命周期 owner 窄审计（本轮只读）

- 仓内生产消费点只有两类：宿主动态路由的 `pageComponent` 注入，以及开发预览直接挂载。入口 `src/main.ts:421` 将 `SparkPageRenderer` 交给 pageNode 配置；备用 `SparkApp.start` 默认选择同一 renderer（`packages/spark-app/src/app/start.ts:301-313`）。`DynamicRouter` 在 `packages/spark-app/src/router/dynamic.ts:212-219` 创建 `PageRuntimePool` 并把 `options.pageComponent` 原样注入；pool 在 `packages/spark-app/src/router/page-runtime-pool.ts:70-106` 创建每个调用唯一的 `PageRuntime`，`L117-128` 用 `h(this.options.pageComponent, { pageRuntime: runtime, routeSnapshot })` 包装它。也就是说，main/start 的 renderer 都在 pool 管理下，不是 renderer 的隐式 owner。

- 第二个生产 owner 是 `src/views/app/dev-system/DevPreviewTab.vue`：直接 `new PageRuntime`（L106）；刷新前释放旧预览（L85-89），加载失败释放局部 runtime（L117-125），组件 `onBeforeUnmount` 释放预览 runtime（L158-160）。它不经过 `PageRuntimePool`，但已有自身明确的终结路径。
