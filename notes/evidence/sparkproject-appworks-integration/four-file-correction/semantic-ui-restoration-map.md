## 同步字段、副作用与确认边界

- 当前输入参数读链：`__init__`→`reloadDesign` 用 `loadFromServer` 读取 `designParameters`；遇到本地 editing 草稿时 `designRebuildFromCurrentViews` 读取现有 DataView，并重建快照。读取、解析和 `designParametersValue` 更新属于加载/内存状态，不是服务器写。
- 打开参数弹窗时 `designOpenParameterEditor` 仅检查快照、`fieldAccess`、`editActionState` 并捕获上下文、打开 dialog；`designParameterEditorBeforeRender` 解析当前 editing row。该打开/渲染路径不调用 `updateEditingValue`、`saveChanges` 或 `loadFromServer`。
- 用户明确编辑后，参数组件 emit `change`→`designChangeInputParameters` 校验并 `updateEditingValue`；这是 DataView 本地编辑草稿，不是服务器保存。点击取消走 `discardEditingRows`。确认按钮才调用 `saveChanges`，检查唯一行回执并 `loadFromServer` 回读。
- 异常回执/回读失败进入 recovery；“放弃本地修改并重新读取”必须再次确认，`discardPendingChanges` 不声称撤销可能已提交服务器的内容。只读页签切换和 node 面板 load/watch 路径必须保持同一规则：只读加载/本地计算可见，不触发同步写；逐入口搜集 watcher、before-render 和 load handler，验证无写 API 副作用。

## 当前阻塞差距、歧义与验收动作

- 当前四文件 rule 未出现节点属性面板或四页签节点编辑能力；必须恢复为 rule/script 主流程 + 窄输入控件，而非 Vue 整页/整面板包装。

- 布局边界：`prepareMissingLayoutRebuild` 只在文件明确不存在时允许准备重建；已有损坏/旧版内容最多导致内存 fallback，报告不得声称缺失与损坏都可直接修复/覆盖。
- 权限按数据维度组织：目录/目标行、模型行、字段行、关系行、`inputParams` 字段分别依 read/write access 与 edit action 控制；admin 是测试账号，没有放行语义。发现任何源角色实现只标“待剔除”，不迁移、不映射到数据权限。

- 最终交互核验动作：逐 D 用例执行原业务任务路径与取消/错误/部分成功路径；逐按钮关联输入、输出、远程调用、持久化与回读；对每个查询/保存使用目标 rowid、table/view 和字段权限证据。

- **查看概览任务**：`r-table` / `RenderDesignParameters` / `RenderDesignLayout` 展示目录信息、参数摘要、布局状态；只读输出，不引入编辑入口。
- **维护模型任务**：`rule.json` 组织模型来源和节点四页签；`script.js` 管理当前节点、来源识别和业务保存序列；每个表单只提交具体字段化值给页面协调器。
- **维护字段任务**：先用 `r-form` / 表格编辑控件承载字段名、类型、别名、输出/计算设置；窄组件仅在输入控件合同不足时承载单个结构化字段，不处理模型列表和保存所有权。
- **维护请求任务**：每一来源类型一个业务表单分支，但共用页面级验证/保存编排；应验证选择来源切换时保留或丢弃草稿的原语义，不能猜测默认策略。
- **维护数组/处理任务**：普通标量字段优先宿主输入组件；数组操作保持增删及业务顺序；数据处理表单配置 addApi/updateApi/deleteApi 的目标模型及目标字段值函数，保存配置本身不执行目标业务 CRUD。窄组件输入明确的结构化值、输出 change，不直连 API。
- **维护关系任务**：图组件恢复节点选择/拖动/连线意图；页面负责端点候选（仅当前数据空间模型）、关系类型、filter/cascade 输入、冲突校验和显式保存结果。拖线先形成待确认/待配置意图，不能绕过四文件验证直接落关系。
- **预览任务**：页面负责选目标模型、参数和触发条件，结果展示优先 `r-table`；图形组件只呈现关系拓扑，不取代数据结果预览。
- **参数维护任务**：现有 dialog + 参数表单承担条目级改动；页面统一验证权限、持久化回执、读后比对和失败恢复。禁止把参数序列化串直接作为用户编辑控件。
- **API 信息任务**：现有只读模型/字段表可做数据基础；新入口应是有权限的按需读取/展示动作，不在页面载入时顺手生成或保存 API 信息。
- **删除任务**：页面显式展示对象、依赖对象及确认点；窄组件只输出用户选择，不决定后台级联含义或权限。

## 节点面板字段同步核对（依据已完成原交互源码报告）

- 原页面 node panel 挂载/切换当前节点：`currentModelId` 与 `state.fields` 的 immediate watch 将已加载字段归一到前端本地草稿；节点 ID watch 读取脱敏规则并调用 `readFrontModelFields` 初始化前端模型页。这两条是本地计算/只读请求，没有调用 `syncModelFields`。
- 切换元模型→前端模型时，使用当下输出字段草稿做本地投影；普通页签切换不写字段。数据处理页若有未保存草稿，离开时弹出“保存并继续/放弃并继续/关闭取消”；只有选择保存并继续才显式调用数据处理保存。
- 用户点击“从来源更新字段”时读取来源并形成 `boundSourceDraft`/字段草稿；该动作不是持久同步。持久同步发生在明确保存闭环（节点配置、数组或前端模型保存）中，必须有用户发起的保存动作。
- 当前 AppWorks `config/.../script.js` 不含节点属性面板 watcher；现有 open/edit 参数流独立，参数打开/切换没有隐式 DataView 写。后续恢复应把原 watcher 语义保留为只读加载/本地投影，并逐 watcher 追踪是否调用 mutation/save；仅据原交互报告记录的具体链为 `node-panel/use-data-set-design-node-panel.ts:525-557,1329-1365,1411-1441,2397-2473` 与 `data/api/data-set/design/data-space-design.ts:554-613`。
- 验收动作：开/关节点属性、切换节点、切换四页签前后比较 DataView editing/pending/dirty 状态与网络 mutation 调用；分别点“从来源更新字段”和“保存”，前者只应改变草稿，后者才可同步并读回字段。对数据处理离开页签三种选择分别核保存、丢弃、保持当前页。

## 整体数据空间语义与当前样板边界

- **整体业务定义（主控确认）**：数据空间是 SPARK 前后端数据交换中心：上接页面功能语义并形成前端数据结构，下接多种后端资源，旁接功能标签及授权等配置。恢复设计器不能缩成“模型关系图 CRUD”；来源/模型/字段/数组/处理/关系/参数/预览是交换链路的一部分，功能标签与授权配置是旁接能力，也必须保留。
- **当前样板入口边界**：本次 D01–D15 和四文件组件图只覆盖“从数据空间目录携带 tenantId、projectId、dataSpaceId 进入单个设计页”的入口，以及该设计页已接入和待恢复的设计任务；不能据此声称当前页已经承载数据空间全部配置面。
- **不扩大无关实现**：在页面恢复范围内，明确保留功能标签/授权配置的可达入口、关联对象、表/行/字段数据权限和持久化/回读验证；未读到的旁接配置结构应标 **合同待证**，不得按猜测新建 API 或数据模型。若它们由同空间其他现有页面负责，本页保留正确链接/关联，不重复实现其所有者。
- **权限边界**：前端无角色概念；数据空间授权配置属于要保留的业务配置，运行时授权结果以数据权限为准。原源码任何角色分支只标待剔除，不迁移、不将 admin 映射成可读写权限。
- **验收动作**：从目录入口追踪功能标签及授权配置的现有对象/页面/关联；核谁拥有读写与保存职责；恢复入口后逐表/行/字段验证可读、遮蔽、只读、可写及权限变化。证明配置被保留且可操作，不以“用户角色”代替数据权限。
