# 五层治理与应用交付研读

## 研读范围

- 五层治理语义：平台管理委派、应用使用授权、企业内部管理、应用设计、页面交付。
- 当前正式入口、会话作用域、系统导航、应用目录、企业入驻、跨企业应用授权、数据空间目录、维度和页面运行链。
- 研读只形成实施依据，不证明线上后端已经提供全部能力。

## 当前源码结论

1. 前端没有角色模型。权限最终由当前登录人、当前执行域、本次正式 DataView 查询/操作的行、字段、动作结果决定。
2. `src/registries/vue-page-registry.ts` 的 `PageScope` 只有 `public/platform/enterprise/app`；不应为“五层”增加五类前端 scope。
3. 平台和企业系统菜单由本地页面登记投影，平台导航当前以有效登录会话启用；这不是平台管理权限。
4. 应用业务导航、正式目录和 DataView owner 才是运行权限和数据真源；`/platform` 的 `homepage` 表示目录执行域，不是同名业务应用的权限。
5. 平台入驻页 `5914` 已有 `Base_Enterprise_Info`、应用授权、模块授权和企业初始化命令；应用使用授权和模块授权是两份独立关系。
6. `enterprise_app_auth` 三个场景绑定不同 modelId：
   - 申请 `0221`：`44a9432c-2fc5-4e1a-9a62-7d528696c4e2`
   - 我的申请 `47DA`：`e666fd6e-ffae-40b4-8622-b6bc2ec1e102`
   - 审核 `C06D`：`6a72428e-27bf-483d-8262-1796e4b49f98`
7. 现有授权测试使用三个场景模型、一个共享内存物理表和一个登录会话。它能验证页面绑定，不证明跨场景线上映射、双租户权限或并发决定。
8. `commitAppAuthRecord()` 只等待 `saveChanges` 不抛错，没有检查 `{success:false}`；存在“明确失败仍提示成功/关闭”的控制路径。
9. 0221 新增视图常驻 `id is-null`，不能靠刷新它找回已提交请求。47DA 列表也不能靠“最新一条”映射正式请求。
10. C06D `default` 含 `PENDING + source_ent + REQUEST` 范围，`audit` 只按 `recordId`；提交前必须再次核对当前登录人的正式权限和业务状态。
11. `90A8` 数据空间目录的跨应用可见只是目录发现，不是共享数据权限；`88A4` 维度定义、规则、来源绑定和 `07D2` 台账不能整场景升格。
12. 项目蓝图、PageTool、ScenarioViewConfig、PageRuntime 已支持应用和页面设计；页面级是应用设计子域，不需要第五类治理 scope。
13. `DataTable` 承载 `resourceType/resourceId/modelBinding/api/crudConfig`、模型级共享 CrudService 与保存约束；`DataView` 持有查询、过滤、分页、选择、编辑及本次状态。低代码 assembler 按 DataTable 契约为各命名视图装配 query/save/file/command owner，页面和脚本不得再声明第二套接口或 save owner。

## 关键调用链

### 跨企业申请

```text
C06D published applications
  -> 0221 enterprise_app_auth add
  -> DataSet.saveChanges
  -> 正式新增键/回执
  -> 47DA my requests 精确回读
C06D review
  -> audit 视图按 recordId
  -> DataSet.saveChanges
  -> A 端 47DA 按正式请求键回读
```

### 平台/企业工作区

```text
登录会话 + 无应用目录域
  -> 当前登录人的正式入口结果
  -> 企业内部事务分区
  -> 受托平台应用分区（有效委派 + 个人正式入口）
  -> 各域独立 DataSet/DataView
  -> 行/字段/动作权限
  -> DataTable 接口/资源配置
  -> assembler owner 装配
  -> DataView owner 提交与精确回读
```

### 管理委派

```text
平台应用正式身份 + 领码科技正式租户 ID
  -> 部署侧一次性初始委派
  -> 逐项回读确认
  -> 后续建立/转移/解除页面
  -> 管理清单
```

管理委派不授予应用使用权、模块、数据共享、默认应用或个人权限。

## 现有改动基线

当前工作树已有大量与本计划无关的未提交底座、生成物、发布运行时和测试修改，且分支为 `main`。本计划只允许落规划文档；实施前必须重新检查状态并确认这些改动不会与目标文件冲突，不得覆盖、重置或纳入本任务提交。

## 已识别的阻塞

1. 平台应用正式身份与领码科技稳定租户 ID 的初始化合同未在当前仓内证实。
2. 独立管理委派模型、关系键、基数、冲突及历史合同未证实。
3. 0221/47DA/C06D 的线上正式请求键映射未证实。
4. 无应用目录域、针对当前登录人的正式入口合同未证实。
5. 跨应用共享的资源粒度、字段/行/动作范围、运行强制和撤销时限未证实。
6. 维度定义的企业归属、应用私有归属与迁移清单未证实。

## 研读结论

架构应按独立关系和执行域实施，不建设五级权限树，也不按“当前企业已获托”自动放行个人。首个产品切片是既有跨企业应用申请的精确双端拒绝与重开回读；部署初始委派是此切片之前的强制门槛。
