## 缺陷—修复—复验闭环

| 严重级别 | 问题 | 修复 | 复验 |
| --- | --- | --- | --- |
| P0 | `hidden` 节点被当作不可路由目标，登录页无法注册 | 将 hidden 收敛为运行菜单可见性；路由目标按真实页面类型投影 | 自动化测试与浏览器登录通过 |
| P1 | 未认证页面建立 SSE，因缺少 lowcode 会话产生未处理错误 | SSE 生命周期改为认证后启动、登出停止 | 登录页无会话错误消失 |
| P0 | 真实蓝图有多个顶层与缺失父记录，严格单根/闭包校验阻断启动 | 保留全部平铺记录，输出诊断，并在编辑器投影合成项目根 | 145 条历史蓝图记录可加载 |
| P0 | 合成根 ID 与持久根记录 ID 冲突，导致渲染主线程阻塞 | 合成根使用 `project-blueprint:<projectId>` 独立身份 | 开发工作台稳定渲染 |
| P1 | 后端图标名 `DataBase`、`FolderOpen` 直接显示成文本 | 增加到 Element Plus 图标的语义别名 | 菜单与按钮显示正常图标 |
| P0 | 非 `vue:` 运行路由的 `conid` 被丢弃，数据库目录无法获得 FormKey | route/vue 目标均保留后端授权 FormKey，外链仍不绑定场景 | 数据库服务器与数据库目录可读 |
| P1 | 数据库目录标注只读但 mutation 按钮可点击 | 目录 mutation 入口全部显式禁用 | 浏览器逐按钮检查均为 disabled |

## 仍需平台数据或后端能力解决的观察项

- 多个历史蓝图节点缺少父记录或可证明的业务节点类型；当前实现保留并诊断，不按标题、URL 或物理表名猜测。
- lowcode 当前可用模型未完整公开 `Base_serverInfo`、`Base_TblField`；数据库目录仍可从已授权模型读取，字段/关系能力按缺口展示。
- Template DSL、仪表盘和能力管理仍包含演示数据，不能当作真实 lowcode 业务闭环。
- 工作流列表在本项目为空；写入/发布需要后端提供具备 preimage、幂等、journal、readback 与补偿的受治理 mutation 后再开放。
- 物理表身份不足以直接读取业务数据；运行数据必须从绑定 FormKey、数据空间和唯一 modelId 的页面闭包进入。

批准范围内的项目蓝图读取、授权运行导航、登录生命周期、图标、数据库只读目录和 mutation 门禁已经形成可复验闭环。未把缺失后端能力伪装成成功，也未执行任何 live 写入。
